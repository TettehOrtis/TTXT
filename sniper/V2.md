Two things drive V2:

1. **The bot runs on a laptop that cannot stay on 24/7.** It must work properly in a window — about
   **07:00–12:00** — and be genuinely safe to walk away from when the laptop closes.
2. **More than one symbol at a time.**

Of the two, the trading window matters more and is cheaper. Build it first, on its own. Multi-symbol can
follow.

## Part 1 — the trading window (do this first)

### The dangerous bit, before anything else

Today, if the laptop closes with a basket open, **nothing manages that basket.** The only thing standing
between you and an open position is the emergency stop at about **−$105**, which exists for exactly this
case and is not meant to be a normal exit.

So the window is not just "don't open trades outside these hours". It is:

| Time | Behaviour |
|---|---|
| Before 07:00 | Idle. Nothing open, nothing opened |
| 07:00 → 11:30 | Normal trading |
| 11:30 → 12:00 | **Wind-down.** Manage open baskets, but open no new ones |
| 12:00 | **Force-flat.** Close anything still open, whatever its P/L |
| After 12:00 | Idle. Safe to shut the laptop |

The wind-down matters. A basket takes ~23 minutes on average but the tail is long, so stopping new
entries half an hour before the end lets most baskets finish on their own terms rather than being
guillotined at a random price.

**It must also be safe to start late.** If the bot is started at 09:00 it should simply begin; if it is
started at 13:00 it should say "outside the window" and sit idle rather than trade.

### What it would do to the numbers

Measured on 2021–2026 with the current settings (daily loss limit raised to $150 so it is not the
binding constraint):

| Window (UTC) | Trades/day | Per month | Win % | $/basket | $/day |
|---|---|---|---|---|---|
| All day (now) | 20.3 | 525 | 89.7% | −$2.05 | −$41.52 |
| **07:00–12:00** | **6.1** | **158** | **90.0%** | **−$1.78** | **−$10.88** |
| 08:00–12:00 | 5.0 | 128 | 90.1% | −$1.71 | −$8.45 |
| 07:00–16:00 | 12.3 | 318 | 89.5% | −$2.16 | −$26.58 |
| 00:00–07:00 (Asia) | 7.4 | 192 | 89.2% | −$2.39 | −$17.71 |

Two honest readings of that table:

- **07:00–12:00 is the least-bad window tested.** −$1.78 a basket against −$2.05 all day. That matches
  BT20's session work, where London (07:00–12:00) lost less per trade than the New York overlap. So the
  window you need for practical reasons also happens to be the better one. That is luck, not skill.
- **It is still negative.** Trading less loses less. It does not win.

About **6 trades a day**, 158 a month. Since Ghana is GMT+0, 07:00–12:00 UTC is 7am–12pm on your clock.

### Settings it would add

```
SNIPER_TRADING_HOURS=07:00-12:00   # blank = all day, as now
SNIPER_WINDDOWN_MINUTES=30         # stop opening new baskets this long before the end
SNIPER_FLAT_AT_WINDOW_END=True     # close everything at the end. Leave ON for laptop use
SNIPER_TIMEZONE=UTC                # UTC or local. Ghana is GMT+0 so they are the same
```

### Work involved

Small. Roughly:

- `config.py` — four new settings plus validation of the `HH:MM-HH:MM` format
- `engine.py` — a `_in_window()` check beside the existing `_weekend_flat_due()`, which already does
  almost exactly this job for Friday. `_maybe_open` gains one guard; `_manage` gains the force-flat
- `telegram.py` — `/status` shows the window and time remaining; alerts on window open and close
- Tests — window open/closed/wind-down, force-flat, starting mid-window, starting outside it

**Estimate: an hour, most of it tests.** It leans on machinery that already exists.

## Part 2 — several symbols at once

### Cost: medium. Not a rewrite, not a one-liner.

The shape of the code already suits it. `Engine` takes a broker and a config, so running three engines is
natural. Four things actually need doing:

1. **One shared MT5 connection.** Today each `Broker` calls `mt5.initialize()` and `mt5.shutdown()`.
   With several, one shutting down would kill the others. Split into a connection owned once by
   `run.py`, and a per-symbol view that only resolves its own symbol and spec.
2. **A state file per symbol.** `logs/sniper/state.XAUUSDz.json` and so on, so each basket recovers
   independently after a restart.
3. **Telegram aggregation.** The `Bus` holds one snapshot; it becomes a dict keyed by symbol. `/status`
   gains a line per symbol, `/positions` groups by symbol, `/close` needs to say which one.
4. **Account-wide risk limits.** The important one — see below.

The magic number needs no change: `positions()` already filters by symbol *and* magic, so one magic
across all symbols is fine.

**Estimate: an hour or so, plus tests.** Mostly mechanical.

### The risk problem — decide this before building

One basket risks **$70**. On a **$444** account that is already 16%.

Three symbols trading at once can hold **three baskets simultaneously — $210, nearly half the account** —
and today's daily loss limit would stop none of it, because it is a *per-bot* limit of $50 and the
baskets are still open, not yet realised.

So V2 needs, at minimum:

```
SNIPER_MAX_OPEN_BASKETS=1          # across ALL symbols. 1 = never two at once
SNIPER_ACCOUNT_DAILY_LOSS=150      # shared across all symbols; when hit, everything stops
```

With `MAX_OPEN_BASKETS=1`, several symbols means "watch three markets, take whichever signals first"
rather than "triple the risk". That is almost certainly what you actually want on a $444 account, and it
also keeps the trade count near today's rather than tripling it.

**Also note:** per-symbol daily limits and an account-wide one are not the same thing, and the account-wide
one is the one that protects you. Per-symbol limits are useful for keeping each symbol's experiment
clean, but they do not cap total damage.

### The $7 / $70 problem when you change instrument

**$7 and $70 are amounts of money, not distances.** They mean completely different things per symbol:

| Symbol | 0.10 lots, what $70 is | Consequence |
|---|---|---|
| XAUUSDz | ~$7 of gold price | What everything was tuned on |
| BTCUSDz | a small move for BTC | Stop hit constantly; baskets die in seconds |
| EURUSDz | an enormous distance | Stop almost never hit; baskets stay open for days |

That last one is genuinely dangerous with a laptop: a basket that never resolves is a basket still open
when you close the lid.

So V2 needs **per-symbol target and stop**, not one pair shared:

```
SNIPER_SYMBOLS=XAUUSD,BTCUSD
SNIPER_XAUUSD_TARGET=7
SNIPER_XAUUSD_STOP=70
SNIPER_BTCUSD_TARGET=15
SNIPER_BTCUSD_STOP=60
```

Before enabling any new symbol, run `sniper.expect --symbol X` against it. **This now works** (it used
to be hardcoded to gold). If a symbol's typical basket runs longer than the trading window, do not trade
it on a laptop.

### MEASURED, 2026-10-06 — and this is the whole argument against currency pairs

All on current settings (target +$15, stop -$70, 0.10 lots), 07:00-12:00 UTC, with the 12:00 force-flat
modelled:

| Symbol | Trades/day | Typical hold | **Cut off by the clock** | $/basket |
|---|---|---|---|---|
| XAUUSD | 4.1 | 9 min | 11% (-$18 each) | **-$1.69** |
| BTCUSD | 2.3 | 45 min | 31% (-$12 each) | **-$1.08** |
| GBPUSD | 1.5 | 97 min | 48% (-$14 each) | **-$1.41** |
| EURUSD | 1.3 | 164 min | **61%** (-$11 each) | **-$1.78** |

**Read the "cut off" column, not the money column.** Before the force-flat was modelled, EURUSD read
**+$4.85 a basket** and GBPUSD **+$1.82** - both looked like the edge this project has never found. They
were not. Those profits came entirely from baskets held for hours past noon, which V2 closes. Once the
clock is honoured, both are losers.

The mechanism is the one predicted above: a $70 stop is 70 pips of EURUSD, which almost never gets hit,
so the basket wins its small +$15 most of the time and sits open for 2-3 hours doing it. That shape needs
a longer day than the laptop has. Gold's $70 is $7 of price, which resolves in 9 minutes.

**Conclusion: do not add a currency pair to a 5-hour window at this stop size.** Gold is the only one of
the four whose baskets reliably finish inside it. BTCUSD is second, but at 0.10 lots it is about $10,000
of bitcoin on a $444 account, so it needs its own (much smaller) lot size before it is even arguable.

One honest caveat on the BTC row: its commission is set to $0 and its spread to $12 in the contract
table, as Exness Zero crypto is spread-only. Those are estimates, not measured like gold's $11/lot. Fix
them from a real fill before trusting that -$1.08.

## Part 3 — smaller things worth folding in

- **`/flat` command** — close everything and stand down, for when you need to shut the laptop in a hurry.
- **A "window closing in 10 minutes" Telegram alert**, so you know not to walk away yet.
- **Startup warning when the numbers contradict each other.** Today the daily loss limit is $50 while a
  single loss is $71.10, so the limit can never do its job. The bot should say so at startup.
- **Report both figures on close.** The first live basket showed "+$14.61" while the account got $14.19.
  Show the decision figure and the settled figure, so they are never confused again.
- ~~**`--window` in `sniper.expect` already exists**~~ — it did, but it only filtered the entry hour.
  It now reads the window straight from `.env` and models the force-flat, and takes `--symbol`:
  ```
  .venv\Scripts\python.exe -m sniper.expect                      # gold, window from .env
  .venv\Scripts\python.exe -m sniper.expect --symbol EURUSD      # another market, same window
  .venv\Scripts\python.exe -m sniper.expect --all-day            # compare against all day
  ```

## The thing that does not change

None of this makes the strategy profitable. BT20 tested 432 entry-and-exit combinations and none made
money across all three eras. The window helps because it trades *less*, not because those hours are good.

V2 is about making the bot **safe to run on a laptop and able to watch more than one market** — which is
worth doing for the forward test. It is not an attempt to find an edge, and nothing here should be read
as one.
